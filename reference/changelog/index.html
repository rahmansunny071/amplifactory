    • #50: sync-root-factory gaps from the first real run (pensieve-traces v0.6.0 to v0.8.0).
      • Bootstrap fits a protected main: extract the release tag's sync-root-factory/ into a temp dir outside the repo (depth-1 fetch of the annotated tag, git archive) and run its sync.py --repo <repo root>. Nothing is committed before the adopt branch exists. This replaces v0.8.0's "copy, commit, run" (see "Adopt in an existing repo"). Every sync, not only the first, now runs the target tag's script, so a repo whose in-repo sync.py predates a fix still gets it.
      • apply syncs every skill folder the tag ships under template/.claude/skills/ (so factory-lesson/ and future skills arrive), not a fixed pair. Old-tag folders are replaced only after verify-local; new folders are added; a folder the old tag lacked but you already have (tracked, untracked, gitignored, a symlink, a case-variant name, even a byte-identical hand copy) is refused with the way out (rename it, or git rm -r it on the adopt branch, commit, rerun); a folder the tag dropped is left alone and listed; your own skills are never touched. Every check for every folder runs before the first write. A repo that hand-copied factory-lesson/ (tracked, from a tag that shipped it) syncs normally; one that added it from a tag that did not must remove it first.
      • labels is never silent: it prints none missing (plus any skipped Actions-only labels) when there is nothing to create.
    • #48: copier-check. sync.py copier-check <tag> runs before copier update in a generated repo: the tag must be annotated, _commit a vX.Y.Z tag, and _src_path the GitHub template (gh:rahmansunny071/agent-factory or its https/ssh URL; a local clone or a fork is refused with the fix: edit the existing line, commit, rerun; a repeated _src_path or _commit line is refused, since Copier keeps the last one). status reports src_ok.

      • scripts/sync.py enforces the guards (new branch local/adopt-<tag> from a fresh origin/<default>, clean tree, never inside agent-factory, files only from the annotated release tag, verify-local before any overwrite, symlinked or out-of-repo target folders refused, only tracked files replaced, only missing labels created, push of that one branch); the agent does the judgement. Every refusal happens before a write, except apply's post-check, which says how to undo.

Once, copy only template/.claude/skills/sync-root-factory from the new release tag (do not re-copy factory/: that would bring its VERSION and skip every hand-port), commit it so the tree is clean, then run the sync with --assume-tag <the tag your existing factory/ folder was copied from> (see "Adopt in an existing repo"). Releases before this one have no VERSION, so --assume-tag is needed that one time.

    • The skill no longer hard-codes "agents may not read real user data".
    • Question: real_data_access (never, with-approval, allowed; default never, so copier update changes behaviour for no one). It renders a ## Real data section in CLAUDE.md whose first line is Real data: <level>..
    • Always on: never commit real data; never quote values from it (field names, counts and shapes only); tests use synthetic fixtures only; read data where it lives and never copy it into the repo or worktree; a stricter hard rule overrides the level.
    • with-approval: the maintainer approves one named source on the issue or PR, for that issue or PR only. Standing access means allowed.
    • Skill: "Reality check" reads the line from CLAUDE.md on main. A missing or unrecognised line means never. Briefs carry the rule to every subagent; reviewers tag real-data values in the diff or text as a blocker.
    • Repos that adopted the skill by hand (such as pensieve-traces) must add a Real data: <level>. line, or run copier update --data real_data_access=<level>; until then they read as never.
    • Template CI renders with-approval and allowed and guards the rendered text.

    • Docs ship with the code (#30).

Docs that disagree with the PR's code break a hard rule, so they're a blocker even in mvp. Mismatches outside the PR's diff are filed, not fixed.
    • Documentation tech-debt issue: one open issue titled exactly "Documentation tech-debt" (documentation, P2) whose native sub-issues (documentation, improvement, P2) are the doc todos. bootstrap.sh creates it and the documentation label; the skill finds it by title and creates it if missing, so existing repos need no re-bootstrap. New lanes.py doc-debt find|add|list. queue.py never lists the tracking issue as work.
    • Skill: the builder updates the docs its change affects and adds a Docs line to the Handoff (docs updated, or "none needed" and why). The code reviewer checks docs against code in the changed area: a mismatch the PR causes is a blocker, an older one is the new doc-debt tag. The orchestrator files doc-debt findings as sub-issues of the tracking issue (not in the PR's improvement issue) and resolves their threads with the link. Ride-alongs: the builder gets the open doc todos and fixes those about files its PR already touches (Closes #N). Documentation todos from planning also go under the tracking issue.
    • New merge gate 12, "Docs ship with the code": the Handoff's Docs line is present, and a diff that changes code but no docs states a reason that holds up. "You aren't unsure" is now gate 13.

    • Fixed along the way: SKILL.md said "Three principles" above four.
    • Ready-to-merge hand-off (#32). When every gate passes but the merge is refused (the harness denies gh pr merge, or GitHub rejects it), that is no longer a dead end.

The end-of-run report lists these PRs so you can merge in one batch.
    • Merge command: plain gh pr merge <PR> --merge --delete-branch when mergeStateStatus is CLEAN; --admin only when the PR is blocked solely by the required review. Gate 2 no longer presents --admin as the only path.

    • v0.5.1 (2026-11-24): Data-loss blocker (#27).     • v0.5.0 (2026-11-24): Swim lanes (#23). Work is organised as prioritized lanes of ordered, dependency-linked issues.
    • Lanes: a parent issue labelled lane whose native GitHub sub-issues are processed one at a time, in order. Priorities P0–P3 on lanes and issues. Dependencies between issues or whole lanes use native "blocked by" links, with the body's "Depends on #N" line kept as a fallback.
    • Brainstorm is two-level: lanes (priorities, lane dependencies, main path), then ordered issues per lane, with rolling-wave detail (only the next one or two issues fully written). One confirmation creates everything.
    • Scheduling: queue.py is lane-aware. Each lane's current issue and state, lanes ranked by priority, "Work now" for --lanes N. One lane at a time by default; the skill asks the maintainer before running more lanes in parallel. A question on a lane pauses only that lane. A collision guard holds a second lane whose plan touches the same files.
    • New scripts/lanes.py (sub-add, order, block, priority, project-add, show) wraps the GitHub sub-issue, dependency and Projects calls.
    • bootstrap.sh creates the lane and P0–P3 labels and a GitHub Project board with a Priority field (needs the project scope).
    • First real test: pensieve-traces restructured into four lanes.
    • v0.4.0 (2026-11-24): Flag and continue (#21). The skill never blocks the session waiting for the maintainer.

The issue and PR get factory:needs-maintainer, and the run moves on to independent work. An in-session question only when nothing else can proceed.
    • Resume ("resume the factory") works from GitHub state: queue.py shows which waiting PRs have new maintainer replies.     • Where knowledge lives: GitHub and the repo are the source of truth; the run log is a local cache and cost ledger that only points at them; Claude's memory holds preferences. New CLAUDE.md section.
    • Gates: new "Handoff present" and "all review threads resolved". bootstrap.sh turns on "require conversation resolution" and creates the factory:needs-maintainer label. gates.md documents the API calls for posting inline questions and for finding and resolving threads.
