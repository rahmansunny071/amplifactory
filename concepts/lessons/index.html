    Concepts

    Lessons¶

    A lesson is a factory problem written down where it can be fixed: an issue labelled lesson in rahmansunny071/amplifactory. Every project the template made shares the same skills, briefs and gates, so one fix there reaches all of them.

    What counts¶

    A lesson is about the factory, not your project's code:

    • a default, question or message in the template that was wrong or misleading;
    • a skill step, brief or gate that made an agent do the wrong thing, or blocked a good PR;
    • a script (queue.py, lanes.py, bootstrap.sh, the runner pool) that failed on realistic input.

    A bug in your project is an ordinary issue in your project.

    File it when it happens¶

    Say it in the session where you hit it:

    file a factory lesson: the builder skipped the Docs line in the Handoff

    The factory-lesson skill finds the template from _src_path in .copier-answers.yml, searches the lesson issues for a duplicate, drafts the body (what happened with links, the fix you applied in the project, the template files to change), checks it for real data, secrets and private paths, and asks you once. It files in the template's repo. It never files in your project. How it picks the repo: Keep up to date.

    Fix the problem in your project first if you can: the lesson records the fix, so the template change is small.

    How it reaches you¶

    1. A release PR (release/vX.Y.Z) closes the lessons it fixes and adds a changelog entry for each. See Evolving the template.
    2. After the tag, say "sync the factory to the latest release" in your project. sync-root-factory opens a PR with the update; you merge it. Or run uvx copier update. See Keep up to date.

    A lesson the template already fixed is answered with the fixing release and the update command, not a new issue.
